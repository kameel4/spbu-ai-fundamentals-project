# Adult Census Income Prediction - Design Document

**Проект:** предсказание категории годового дохода человека по признакам из Adult / Census Income dataset.  
**Тип задачи:** supervised learning, бинарная классификация на табличных данных.  
**Target:** `income`.  
**Положительный класс:** `>50K`.  
**Финальная модель:** `GradientBoostingClassifier` из `scikit-learn`.

---

## 1. Goal and metrics

### Что решаем

Цель проекта - построить  ML-модель, которая по социально-демографическим и рабочим признакам человека предсказывает, превышает ли его годовой доход 50 000 долларов:

- `0` - `<=50K`;
- `1` - `>50K`.


### Почему одной метрики  accuracy недостаточно

В данных есть дисбаланс классов: класс `<=50K` встречается сильно чаще, чем `>50K`. Поэтому модель, которая всегда предсказывает majority class, уже может получить заметную accuracy, но не будет хорошо решать задачу для положительного класса. Из-за этого accuracy используется только как вспомогательная метрика.

### Метрики

| Метрика | Зачем используется |
|---|---|
| `accuracy` | Общая доля правильных ответов; может быть обманчивой при дисбалансе |
| `balanced_accuracy` | Среднее качество по классам, лучше показывает качество при несбалансированном target |
| `precision` для `>50K` | Показывает, какая доля предсказанных объектов класса `>50K` действительно относится к этому классу |
| `recall` для `>50K` | Показывает, какую долю настоящих объектов класса `>50K` модель смогла найти |
| `F1` для `>50K` | F1 = 2 * precision * recall / (precision + recall) |
| `ROC-AUC` | Показывает качество ранжирования объектов по вероятности класса `>50K`; используется как основная метрика при `GridSearchCV` |

Основная метрика для выбора финальной модели - **ROC-AUC**, потому что модель возвращает вероятности, и важно оценивать не только итоговый класс, но и качество ранжирования объектов по вероятности принадлежности к классу `>50K`

## 3. Validation draft

### Схема разбиения данных

В текущем проекте используется следующий пайплайн:

1. Загружаются `adult.data` и `adult.test`
2. Два файла объединяются в один dataframe
3. Выполняются очистка данных и удаление дубликатов

5. Данные делятся на train/test через `train_test_split`
6. Используется `stratify=y`, чтобы сохранить доли классов
7. Используется `random_state=42`, чтобы результаты быливоспроизводимыми

|---|---:|

Для подбора гиперпараметров используется:

```python
StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
```

Такая модификация 5FoldCV выбрана в силу дизбаланса классов: стратификация как раз и решает эту проблему

## 4. Approach

### Очистка данных

Очистка данных выполняется до обучения модели

Основные шаги:

1. Задать имена колонок вручную.
2. Пропустить первую служебную строку в `adult.test`.
3. Удалить лишние пробелы в строковых признаках.
4. Заменить `?` на `NaN`.
5. Нормализовать target в `adult.test`, убрав точку в конце значения.
6. Удалить дубликаты.
7. Сбросить индекс.

Пропуски не удаляются сразу, потому что это может привести к потере данных и искажению распределений. Вместо этого они обрабатываются внутри preprocessing pipeline.

### Feature engineering

Добавленные признаки:

| Признак | Как считается | Зачем нужен |
|---|---|---|
| `is_married` | `1`, если `marital_status` равен `Married-civ-spouse` или `Married-AF-spouse` | Упрощает семейный статус до бинарного признака. |
| `native_country_group` | `United-States`, `Other`, `Unknown` | Уменьшает cardinality признака `native_country`. |
| `workclass_group` | Группировка `workclass` в `Private`, `Government`, `Self-employed`, `Other`, `Unknown` | Делает признак устойчивее и компактнее. |
| `hours_per_week_bin` | Бины: `part_time`, `full_time_40`, `over_40`, `extreme` | Добавляет нелинейное представление рабочих часов. |
| `capital_net` | `capital_gain - capital_loss` | Объединяет два денежных признака в один итоговый показатель. |
| `has_capital_gain` | `1`, если `capital_gain > 0` | Фиксирует сам факт наличия capital gain. |
| `has_capital_loss` | `1`, если `capital_loss > 0` | Фиксирует сам факт наличия capital loss. |

Эти признаки добавлены, потому что Adult содержит смешанные типы данных и потенциально нелинейные зависимости. Feature engineering помогает сделать данные более удобными для классических моделей.

### Preprocessing pipeline

Для числовых признаков используется:

```python
SimpleImputer(strategy="median")
StandardScaler()
```

Для категориальных признаков используется:

```python
SimpleImputer(strategy="constant", fill_value="Unknown")
OneHotEncoder(handle_unknown="ignore", sparse_output=False)
```

Объединение выполняется через:

```python
ColumnTransformer([
    ("num", numeric_transformer, numerical_features),
    ("cat", categorical_transformer, categorical_features),
])
```

### Обоснование выбора методов

| Метод | Почему используется |
|---|---|
| `SimpleImputer` | В данных есть пропуски, закодированные как `?`. |
| Медиана для числовых признаков | Устойчивее среднего при выбросах. |
| `Unknown` для категориальных признаков | Сохраняет информацию о том, что значение отсутствовало. |
| `OneHotEncoder` | Подходит для категориальных признаков в классических sklearn-моделях. |
| `handle_unknown="ignore"` | Pipeline не падает при новых категориях на test. |
| `StandardScaler` | Нужен для Logistic Regression и KNN, чувствительных к масштабу признаков. |
| `Pipeline` | Делает preprocessing воспроизводимым и снижает риск data leakage. |
| `ColumnTransformer` | Позволяет отдельно обрабатывать числовые и категориальные признаки. |

## 5. Training

### Модели-кандидаты

В проекте используются  классические ML-модели:

| Модель | Краткая информация |
|---|---|
| `DummyClassifier` | Baseline-модель |
| `LogisticRegression` | Интерпретируемая линейная модель |
| `KNeighborsClassifier` | Метод ближайших соседей; нелинейная базовая модель.|
| `DecisionTreeClassifier` | Дерево решений как базовая нелинейная модель |

Нейросети не используются, потому что по правилам проекта они требуют отдельного согласования, а для табличного Adult dataset достаточно классических методов.

## 6. Validation

### Финальная оценка

Лучшая модель по cross-validation - `GradientBoostingClassifier`. Финальная оценка была выполнена на отложенной test-части после stratified `train_test_split`.

Финальные test-метрики:

| Metric | Value |
|---|---:|
| Accuracy | 0.8765 |
| F1 | 0.7177 |
| Balanced Accuracy | 0.8009 |
| ROC-AUC | 0.9294 |

### Classification report

| Class | Precision | Recall | F1-score | Support |
|---|---:|---:|---:|---:|
| `<=50K` / 0 | 0.90 | 0.95 | 0.92 | 7 422 |
| `>50K` / 1 | 0.79 | 0.66 | 0.72 | 2 336 |
| Accuracy |  |  | 0.88 | 9 758 |
| Macro avg | 0.84 | 0.80 | 0.82 | 9 758 |
| Weighted avg | 0.87 | 0.88 | 0.87 | 9 758 |

### Confusion matrix

|  | Predicted `<=50K` | Predicted `>50K` |
|---|---:|---:|
| Actual `<=50K` | 7 021 | 401 |
| Actual `>50K` | 804 | 1 532 |

### Анализ результата

Модель хорошо определяет класс `<=50K`, но хуже находит положительный класс `>50K`. Recall для `>50K` равен примерно `0.66`, то есть часть объектов с доходом `>50K` ошибочно классифицируется как `<=50K`.

Главный тип ошибки - false negatives для класса `>50K`:

- **804** объекта с настоящим классом `>50K` были предсказаны как `<=50K`;
- **401** объект с настоящим классом `<=50K` был предсказан как `>50K`.

`ROC-AUC = 0.9294` показывает, что модель хорошо ранжирует объекты по вероятности класса `>50K`, даже если стандартный threshold `0.5` не идеально оптимален для recall/F1.

## 7. Model selection

### Финальный выбор

Финальная модель - `GradientBoostingClassifier`.

Лучшие параметры:

```python
{
    "model__learning_rate": 0.1,
    "model__max_depth": 3,
    "model__n_estimators": 200,
    "model__subsample": 1.0
}
```

### Почему выбрана эта модель

| Причина | Объяснение |
|---|---|
| Лучший CV `ROC-AUC` | `GradientBoosting` получил `0.9247`, что выше, чем у `LogisticRegression` (`0.9103`). |
| Хорошее качество на test | На test split модель получила `ROC-AUC = 0.9294` и `F1 = 0.7177`. |
| Подходит для табличных данных | Бустинг часто хорошо работает на табличных задачах с нелинейными зависимостями. |
| Не требует нейросетей | Модель полностью соответствует ограничению на классические методы. |
| Работает внутри sklearn pipeline | Preprocessing и модель можно сохранить как единый воспроизводимый объект. |

### Почему не выбрана Logistic Regression

`LogisticRegression` остаётся хорошим интерпретируемым baseline, но уступила `GradientBoosting` по главной метрике `ROC-AUC`:

| Model | Best CV ROC-AUC |
|---|---:|
| GradientBoosting | 0.9247 |
| LogisticRegression | 0.9103 |

Adult dataset содержит нелинейные зависимости и взаимодействия категориальных признаков. Бустинг может учитывать такие зависимости лучше, чем линейная модель.

### Основные риски и ограничения подхода

| Риск / ограничение | Почему важно |
|---|---|
| Меньшая интерпретируемость | `GradientBoosting` сложнее объяснить, чем `LogisticRegression`. Для защиты стоит использовать feature importance или permutation importance. |
| Историчность датасета | Данные основаны на переписи 1994 года и не отражают современный рынок труда. |
| Корреляция, а не причинность | Модель находит статистические связи, но не объясняет причины высокого или низкого дохода. |
| Стандартный threshold `0.5` | Порог может быть не оптимален для F1 или recall положительного класса. |
